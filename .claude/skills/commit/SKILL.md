# 커밋 규칙

## 절차
1. `git branch --show-current` 로 현재 브랜치를 확인한다. (아래 "브랜치" 규칙 참고)
2. `git status`, `git diff` 로 변경 내용을 확인한다.
3. 변경을 **원자적 단위**로 나눈다. (아래 "원자적 커밋" 참고)
4. 아래 "커밋 전 검증"을 실행한다. 실패하면 커밋하지 않고 원인을 알린다.
5. 커밋할 파일을 **이름으로 지정**해서 스테이징한다. (`git add -A`, `git add .` 금지)
6. 메시지 초안을 사용자에게 보여 주고 **승인을 받은 뒤** 커밋한다.
7. 커밋 후 `git log --oneline -3` 과 `git status` 로 결과를 확인해 보고한다.

## 커밋 전 검증
- 커밋 전에 `npx tsc --noEmit` 으로 타입 검사를 실행한다.
- `package.json` 에 `test` 스크립트가 생기면 `npm test` 도 실행한다.
- 하나라도 실패하면 커밋하지 않는다. 실패 출력과 원인을 사용자에게 보고하고, 고칠지 물어본다.
- `docs`, `chore` 중 코드를 건드리지 않는 변경(문서, 스킬 파일 등)은 검증을 생략할 수 있다.

## 원자적 커밋
- 한 커밋은 **하나의 논리적 변경**만 담는다. 이 커밋 하나만 `revert` 해도 다른 기능이 깨지지 않아야 한다.
- 각 커밋은 **그 시점에 타입 검사가 통과하는 상태**여야 한다. 아직 쓰이지 않는 import 만 남기거나 미완성 코드를 커밋하지 않는다.
- **포맷 정리**(Prettier 등 공백, 따옴표, 줄바꿈만 바꾸는 변경)와 **로직 변경**은 섞지 않고 따로 커밋한다. 포맷 정리는 `chore` 로 한다.
- 구현과 그 구현의 테스트는 같은 커밋에 넣는다.

## 브랜치
- 현재는 **브랜치를 나누지 않고 `main` 에서 직접 커밋**한다. 사용자가 요청하지 않으면 브랜치를 만들지 않는다.
- 나중에 브랜치 전략을 도입하면 이 섹션을 수정한다. (예: `type/영문-내용` 형식, 목적당 브랜치 하나)

## 메시지 형식
```
type(scope): 한글 제목

- 세부 내용 1
- 세부 내용 2
```

- **제목**: 한글, 50자 안팎, 마침표 없음, "~추가", "~수정", "~변경" 처럼 명사형으로 끝낸다. `wip`, `temp`, `수정`, `asdf` 처럼 변경 내용을 알 수 없는 제목은 쓰지 않는다.
- **scope**: 선택. 도메인이나 영역 이름을 쓴다. (`member`, `board`, `config`, `spec` 등)
- **본문**: 변경의 세부사항을 `- 내용` 형태의 목록으로 쓴다. **최대 4줄**까지만 쓰고, 한 줄에 하나의 변경만 담는다. 세부사항이 필요 없을 만큼 작은 변경이면 본문을 생략해도 된다.
- **`fix`, `refactor` 의 사유**: 이 두 type 은 본문에 **사유를 반드시 포함**한다. 사유도 4줄 제한에 포함되며, 별도 줄로 쓴다.
  - `fix`: 무슨 문제였고 원인이 무엇이었는지 (`- 원인: ...`)
  - `refactor`: 왜 구조를 바꿨는지 (`- 사유: ...`)

## type 종류
| type | 용도 |
|---|---|
| `feat` | 새 기능, 새 파일 구조 |
| `fix` | 버그 수정 |
| `refactor` | 동작 변경 없는 구조 개선 |
| `docs` | 문서(설계 문서 포함) |
| `test` | 테스트 추가/수정 |
| `chore` | 설정, 의존성, 빌드 |

## 커밋하지 않는 것
- `.env`, 비밀번호나 키가 들어 있는 파일
- `node_modules/`, `dist/`
- 사용자가 요청하지 않은 임시 코드(디버그용 `console.log` 등). 발견하면 커밋 전에 알린다.

## 금지
- 사용자가 요청하지 않으면 `git push` 하지 않는다.
- `--no-verify`, `--amend`, `reset --hard`, `push --force` 는 사용자가 명시적으로 요청할 때만 쓴다.
- 훅이 실패하면 우회하지 말고 원인을 고친다.
- `wip`, 임시 저장용, 미완성 커밋을 만들지 않는다. 작업이 덜 끝났으면 커밋하지 않는다.

## 작성자 표시
`Co-Authored-By` 같은 AI 작성자 표시 줄은 **붙이지 않는다.** 커밋 메시지는 위 형식의 내용만 담는다.
